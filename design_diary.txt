Date: 2026-10-04
Stage: Binary File Transfer Engine (PUT & GET)

Key Decisions Made:
1. Exact Byte-Count Transfer:
   - Implemented binary streaming for PUT and GET commands. The protocol transmits 
     exact <filesize> bytes sequentially after the single-line control command.
   - Handled partial recv() chunks using iterative buffer loops to ensure exact 
     byte integrity without truncating files.

2. Storage Isolation:
   - Configured Agent to save all uploads under the personalized directory path:
     ./agentfiles/IT24103315/<filename>
   - Enforced a 10MB maximum file size ceiling to prevent memory/disk exhaustion, 
     returning ERR 004 FILE_TOO_LARGE upon exceeding limits.

3. Download & Error Handling:
   - Implemented GET handling ensuring verification of file existence before 
     dispatching OK FILE_SEND. Missing files return ERR 005 FILE_NOT_FOUND.
   - Byte-for-byte verification confirmed matching hashes between original and 
     downloaded files.

Obstacles & Solutions:
- Challenge: Line buffering mixed with binary stream caused blocking when using 
  unbuffered recv.
- Solution: Created a dedicated read_line() helper for control commands that 
  stops precisely at '\n', leaving the subsequent socket stream aligned for 
  exact binary reading.
